# AI Skills — процесс разработки с ИИ под контролем

Набор навыков для Claude Code (и совместимых агентов): один общий
процесс + платформенные правила для Symfony, WordPress, OpenCart.
Живёт в репозитории проекта, версионируется и тестируется как код.

## Состав

```
skills/
  workflow/               общий процесс: план → MVP → итерации,
    SKILL.md              парковка идей, отчёт шага, минимализм
    templates/            PLAN, STEP-REPORT, IDEAS, STUBS, MAP
  platform-symfony/       запреты, идиомы, автопроверки Symfony
  platform-wordpress/     то же для WordPress
  platform-opencart/      то же для OpenCart
checks/
  skill-checks.md         проверочные задачи для самих навыков
```

## Установка в проект (через clone, без ручной настройки у каждого)

1. Скопируй содержимое в репозиторий проекта:
   - навыки → `.claude/skills/` (каждая папка навыка целиком),
   - `checks/` → куда удобно, например `docs/ai/checks/`.
   В проект кладутся ТОЛЬКО нужные платформенные навыки
   (Symfony-проекту не нужен opencart-навык).
2. Создай `docs/` с пустыми `IDEAS.md`, `STUBS.md` и `MAP.md`
   (заполнить карту — первая задача для ИИ под твоим ревью).
3. Закоммить. С этого момента правила приезжают через `git clone`.

## Принципы сопровождения

- **Правила = код.** Изменение навыка — отдельный PR, не вперемешку
  с фичами. Перед слиянием — прогон задач из `checks/skill-checks.md`
  в чистой сессии на тестовой копии.
- **Вендоринг вместо внешних плагинов.** Идеи из чужих наборов
  (Superpowers, Ponytail и т.п.) переносятся в эти SKILL.md выборочно,
  с пометкой источника. Внешние плагины не ставятся: они обновляются
  без вас и молча меняют поведение.
- **Версия правил в отчётах.** Каждый отчёт шага содержит коммит
  правил — всегда видно, по каким правилам писался код.
- **Автопроверки тоже в репо.** phpcs/phpstan/cs-fixer с конфигами —
  в composer dev-зависимости проекта, чтобы приезжали через clone.

## Порядок внедрения

1. Обкатать `workflow` на одной небольшой задаче.
2. Добавить платформенный навык основной системы; остальные — позже
   по той же структуре.
3. Подключить автопроверки (композер + конфиги) в репо.
4. Прогнать `checks/skill-checks.md`, поправить навыки по результатам.

## Рабочий цикл (шпаргалка заказчика)

1. Ставишь задачу → ИИ задаёт вопросы → показывает PLAN.md → ты
   утверждаешь.
2. ИИ делает MVP-срез → ты проходишь его руками по разделу
   «Как проверить» отчёта.
3. Смотришь раздел «Сверх задачи» отчёта и STUBS.md → выбираешь цель
   следующей итерации (новая сессия ИИ).
4. Между итерациями разбираешь IDEAS.md.
5. Раз в 3–4 шага ИИ сверяет систему с MAP.md.
