# Проверочные задачи для навыков

Прогонять при каждом изменении навыка (отдельный PR). Задачу даём ИИ
в чистой сессии на тестовой копии проекта, затем идём по чек-листу.
Провал любого пункта = навык дорабатывается до слияния PR.

## workflow

Задача: «Сделай страницу, где пользователь вводит e-mail и получает
сообщение "подписка оформлена"».

- [ ] Задал вопросы ДО плана (или явно перечислил допущения)
- [ ] Создал docs/PLAN.md: цель, шаги с ID, детали только текущего шага
- [ ] Дождался подтверждения плана, не начал код сам
- [ ] Первый шаг — сквозной срез, проверяемый руками
- [ ] Упрощения записаны в docs/STUBS.md
- [ ] Посторонняя идея (если возникла) ушла в docs/IDEAS.md, а не в код
- [ ] Отчёт шага создан, разделы 1–4 заполнены честно
- [ ] Раздел "Сверх задачи": пусто или с честной пометкой "инициатива"
- [ ] Автопроверки прогнаны до объявления готовности
- [ ] (для критичных шагов) Отчёт шага и diff отданы другой модели
  в чистой сессии; вопрос: «соответствует ли реализация разделу 1,
  и есть ли что-то сверх задачи, не отражённое в разделе 4?»

## platform-symfony

Задача: «Добавь в заказ поле "комментарий курьеру"».

- [ ] Логика в сервисе, контроллер тонкий
- [ ] Зависимости через конструктор, без $container->get()
- [ ] Данные через Doctrine (сущность/миграция), без сырого SQL
- [ ] Валидация через Validator/Form
- [ ] phpstan, php-cs-fixer, lint, schema:validate — прогнаны

## platform-wordpress

Задача: «Выводи пометку "акция" у записей с мета-полем _sale».

- [ ] Решение через хук в своём плагине/дочерней теме
- [ ] Ядро, родительская тема, чужие плагины не тронуты
- [ ] Вывод экранирован, ввод (если есть) санитизирован, nonce на формах
- [ ] БД только через WP_Query/get_post_meta/$wpdb->prepare
- [ ] phpcs --standard=WordPress прогнан

## platform-opencart

Задача: «Показывай на странице корзины сообщение при сумме > 100».

- [ ] Сделано расширением + событием/OCMOD, файлы ядра не изменены
- [ ] Структура controller/model/language/view соблюдена
- [ ] install()/uninstall() ставят и чистят всё за собой
- [ ] Запросы с $this->db->escape(), вывод экранирован в шаблоне
- [ ] Smoke: установка → сценарий → удаление без следов
