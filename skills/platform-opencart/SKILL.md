# OpenCart: запреты, идиомы, проверки

Процесс задаёт `skills/workflow/SKILL.md`. Здесь — идиомы OpenCart.
Сначала определи версию (3.x или 4.x) по структуре: 4.x — пространства
имён `Opencart\`, расширения в `extension/`; 3.x — `catalog/`/`admin/`
в корне, OCMOD. Механизмы расширения у версий разные — не смешивай.

## Запреты

- НЕ правь файлы ядра (system/, catalog/, admin/ вне своего
  расширения). Изменения чужого кода — только через событийную систему
  (events) или OCMOD/модификаторы. Правка ядра ломает обновления
  и конфликтует с другими модулями.
- НЕ пиши в БД мимо `$this->db->query()` с экранированием
  `$this->db->escape()`; структуру таблиц меняй только в install()
  своего расширения.
- НЕ клади логику в шаблоны Twig — только вывод.
- НЕ обходи MVC(+L): контроллер → модель (данные) → язык → шаблон.
- НЕ выводи пользовательские данные без экранирования в шаблоне.
- НЕ дублируй возможности ядра (корзина, валюты, налоги, события,
  кэш) собственными реализациями.

## Идиомы (как делается типовое)

- Новая функциональность: собственное расширение/модуль со своими
  controller / model / language / view, с install()/uninstall().
- Вмешательство в чужое поведение: подписка на событие
  (`before`/`after` контроллеров и моделей) из install() своего
  расширения; если события нет — OCMOD (3.x) с минимальным,
  узким патчем.
- Настройки модуля: через стандартный механизм настроек расширений,
  права — через user_group permissions.
- Перед созданием нового посмотри, как устроен аналогичный штатный
  модуль той же версии, и повтори структуру.

### Так / не так

```
ТАК: расширение + событие
- extension/myproj/... : controller/model/language/view
- в install(): addEvent('myproj_total',
    'catalog/controller/checkout/cart/before', 'extension/myproj/...')

НЕ ТАК:
- правка catalog/controller/checkout/cart.php напрямую ❌
- SQL со вставкой пользовательского ввода без $this->db->escape() ❌
```

## Автопроверки (гонять перед отчётом шага)

- `vendor/bin/phpcs` с конфигом репо (PSR-12 или принятый в проекте
  стандарт) по файлам своего расширения
- `vendor/bin/phpstan analyse` по своему расширению (уровень из
  конфига репо)
- Ручной smoke на тестовой площадке: установка расширения,
  целевой сценарий, удаление без следов (uninstall чистит за собой)

Результаты — в раздел "Автопроверки" отчёта шага.
